# AI 路由启用与禁用

AI 路由列表增加“路由状态”列、筛选以及启用/禁用操作。旧记录缺少 `enabled` 字段时按启用处理。

```http
PUT /v1/ai/routes/{name}/status
Content-Type: application/json

{"version":"当前查询返回的版本","enabled":false}
```

沿用登录/Basic 鉴权。成功返回 HTTP 200 和更新后的 AI route 对象（与现有 PUT 一致，不包装 `data`）。缺少参数返回 400，版本冲突返回 409。请求后通过 GET 回读最新版本，不重用旧版本。

禁用保留 AI route ConfigMap、路由级 WasmPlugin、消费者鉴权、模型映射和备用配置；只删除主、备用 Ingress，并检查已删除。备用 EnvoyFilter 保留为不匹配任何现存目标路由的配置。重新启用根据保留定义重建转发资源。禁用期间编辑路由不会重建 Ingress；旧客户端未提交 `enabled` 时保留原状态。

路由禁用不代表模型在整个网关不可达：同一模型如仍有其他精确、前缀、共享或普通 HTTP 路由入口，仍可能被调用。模型下架工具必须检查全部入口；不能为一个模型禁用整条共享路由。价格、用量记录和历史账单不随路由状态删除。

## 并发与失败恢复

AI 路由增删改和状态切换通过 Kubernetes ConfigMap 的原子创建获取每路由写锁，跨控制台实例互斥。先检查版本，再操作资源；禁用删除失败不写入 `enabled=false`，返回错误，回读后可重试。重新启用失败会尝试撤除部分已生成的转发资源，保留原禁用状态。

写锁名为 `ai-route-write-<UUID.nameUUIDFromBytes(routeName)>`，包含 `route` 和 `startedAt`，不带 AI route 业务标签。正常请求在 finally 释放。**锁不自动过期**，避免暂停中的旧写入者恢复后与新请求并发写。若进程崩溃留下锁，运维须先确认原写入进程已终止、核对对应 ConfigMap/Ingress/插件状态，再删除该锁并重试；不要只凭锁年龄自动删除。

控制台 API 的成功表示配置持久化和 Kubernetes 资源操作完成，网关仍有配置传播时间。下架验收须等待实际网关请求失效并确认其他模型不受影响，不将瞬间的 API 回读当作流量验收。

回退旧版控制台前，先导出所有禁用路由及插件，并制定恢复或保持停用的操作方案。旧版本不理解状态字段，编辑可能重新建立转发资源，不能直接回退后继续管理禁用记录。
